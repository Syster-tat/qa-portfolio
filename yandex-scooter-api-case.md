# Яндекс Самокат: проверка API и данных при удалении курьера

## Контекст

Учебный дипломный проект по ручному тестированию. Проверяла API создания и удаления курьеров и получения заказа по номеру. Для части проверок сверяла ответы API с состоянием базы данных. Ниже — краткий кейс по результатам моего дипломного чек-листа; статусы относятся к моменту учебного тестирования, а не к текущей версии сервиса.

## Как строила проверки

- **Создание курьера:** допустимые и недопустимые значения `login`, `password` и `firstName`, пустые поля, границы длины и повторное использование логина. После успешного создания сверяла появление записи в таблице `Couriers`.
- **Удаление курьера:** ответ API, удаление записи из `Couriers` и состояние связи с уже назначенным заказом. Отдельно проверяла пустой и некорректный идентификатор.
- **Получение заказа по номеру:** существующий номер, отсутствующий номер, несуществующий номер и структура ответа по документации.

## Пример найденного дефекта: связь с заказом после удаления курьера

**Предусловие:** создан курьер; ему назначен заказ.

1. Удалить этого курьера через API.
2. Проверить, что запись о курьере удалена из таблицы `Couriers`.
3. Проверить, что в базе не осталось записи о прикреплении заказа к удалённому курьеру.

**Ожидание по проверке:** после удаления курьера запись о его прикреплении к заказу отсутствует.

**Фактический результат в дипломном чек-листе:** удаление курьера и удаление его записи из `Couriers` отмечены как `PASSED`; проверка удаления связи с заказом отмечена как `FAILED`. Запись о закреплении заказа за удалённым курьером оставалась в базе. Дефект был зарегистрирован под номером `TATYANA-52`.

**Почему это важно:** при проверке только ответа API проблема не видна. Сверка данных показала, что удаление сущности не привело к ожидаемому изменению связанной записи.

## Другие результаты из чек-листа

| Проверка | Результат в дипломе |
| --- | --- |
| Создание курьера с уникальным латинским `login` и проверка записи в `Couriers` | `PASSED` |
| Повторное использование `login` с ожиданием `409 Conflict` | `PASSED` |
| Недопустимые символы и длины в `login`, `password` и `firstName` | Несколько `FAILED`; заведены дефекты `TATYANA-37`, `TATYANA-38`, `TATYANA-39` |
| Получение заказа по существующему номеру | `PASSED` |
| Соответствие структуры ответа на получение заказа документации | `FAILED`, дефект `TATYANA-40` |
| Запрос заказа без номера и с несуществующим номером | `PASSED` |

Примеры запросов и ответов не сохранены в этом кейсе; конкретные значения и тексты ответов не восстановлены по памяти.
